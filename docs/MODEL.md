# Propagation & Attack-Surface Model — Specification

This document is the normative definition of the models used by the digital twin.
Three independent implementations follow it and must agree numerically:

| Implementation | Where | Purpose |
|---|---|---|
| GLSL fragment shader (GPU) | `web/src/rf/shaders.js` | real-time maps in the browser (≈ 200 k cells / update) |
| JavaScript (CPU) | `web/src/rf/model.js` | single-link budgets (attacker, clients), statistics |
| NumPy reference | `sim/twin/mwm.py` | batch maps, comparison against Sionna RT, calibration |

NVIDIA **Sionna RT** (`sim/run_sionna.py`) is the physics reference (ray tracing with
reflection, refraction/transmission and diffuse scattering on ITU-R P.2040 materials).
The real-time model is an engineering model; Sionna is used to validate and calibrate it.

All geometry comes from `data/building.json` (generated by `tools/generate-building.mjs`).

---

## 1. Coordinate frame

* Plan **x → east**, **y → north**, **z ↑**, metres. Origin = building centre at ground level.
* Azimuth `az` is measured in the plan from **+x towards +y** (math convention).
  `az = 90°` points north (into the building from the street façade).
* Tilt / elevation is positive upwards. `tilt = −90°` points straight down.

## 2. Path loss between a transmitter T and a receiver R

```
d      = max(|R − T|, d_min)                   (3-D distance, d_min = 0.5 m)
PL0(f) = 20·log10(f_GHz) + 32.44               (free-space loss at 1 m, dB)
PL     = PL0(f) + 10·n·log10(d) + Σ L_wall + Σ L_slab
```

`n = rf.pathloss_exponent` (2.0 → COST-231 Multi-Wall Model on top of free space).

### 2.1 Wall crossings (3-D)

Every wall is a vertical rectangle: plan segment `a → b`, vertical extent `[z0, z1]`
(absolute), base material `mat`, optional `opening`.

1. Intersect the plan projections of `T→R` (parameter `t`) and `a→b` (parameter `u` ∈ [0,1]).
   A crossing exists for `ε < t < 1 − ε` and `−ε ≤ u ≤ 1 + ε` with ε = 10⁻⁵ (an end point lying on a
   wall plane never counts that wall; a ray through a wall junction counts every wall meeting there).
   Parallel segments never cross.
   *Tolerances.* The geometry and the map grids lie on a regular lattice, so exact coincidences occur
   (rays through junctions, crossings exactly at a sill, head, opening edge or storey boundary). All
   boundary tests therefore use the tolerances above for `t`, `u` and δ = 10⁻⁴ m for lengths/heights
   (`z0 − δ ≤ zc ≤ z1 + δ`, `−δ ≤ m ≤ width + δ`, `sill − δ ≤ h ≤ head + δ`, slab footprint ± δ; with a
   period, `m > period − δ` wraps to `m − period`). This makes float32 (GPU) and float64 (CPU, NumPy)
   decide every coincidence the same way.
2. Height of the ray at the crossing: `zc = T.z + t·(R.z − T.z)`.
   The wall is crossed only if `z0 − δ ≤ zc ≤ z1 + δ`.
3. Material at the crossing point: let `s = u·|b − a|` (metres along the wall),
   `h = zc − z0`. With an opening `{sill, head, period, width, offset, mat}`:
   ```
   m = s − offset ;  if period > 0:  m = m mod period   (positive modulo)
   inside = (0 ≤ m ≤ width) and (sill ≤ h ≤ head)
   ```
   If `inside`, the opening material is used, otherwise the wall material.
4. `L_wall = loss[material][f]` from `materials` (dB), plus protection modifiers (§5).

Wall thickness is used only for 3-D geometry, not for intersections (walls are their centre planes).

### 2.2 Floor slabs

Slab planes are at `rf.slab_planes` (mid-plane of each slab, incl. the roof). For each plane
`zs` strictly between `T.z` and `R.z`: `t = (zs − T.z)/(R.z − T.z)`; if the plan point
`T.xy + t·(R.xy − T.xy)` lies inside `rf.slab_extent` (the building footprint, inclusive),
add `L_slab = loss.slab[f]`. Context buildings have no slabs.

## 3. Antennas

Direction unit vector `v = (R − T)/|R − T|`; elevation `el = asin(v.z)`.

**Half-wave dipole (vertical) — the default router antenna**, peak 2.15 dBi:
```
F(el) = cos(π/2 · sin el) / cos el          (F = 0 when cos el < 1e-3)
G     = 2.15 + 10·log10(max(F², 10^−3))     (dBi, floor at −27.85 dBi)
```

**Directional patch (3GPP TR 38.901 element)** — parameters depend on the mount (`router.mounts.*.patch`):
wall mount `Gmax = 8 dBi, HPBW = 65°, SLA = 30 dB` (aimed inwards, az 90°, tilt −10°);
ceiling mount `Gmax = 5.5 dBi, HPBW = 110°, SLA = 25 dB` (wide-beam ceiling panel, boresight straight down).
A custom (dragged) position uses the wall-mount antenna.
Boresight `b = (cos t·cos a, cos t·sin a, sin t)` with `a = az`, `t = tilt`.
Local frame: `y' = (−sin a, cos a, 0)`, `z' = b × y'`.
```
φ' = atan2(v·y', v·b)     θ' = asin(clamp(v·z', −1, 1))
A_H = −min(12·(φ'/HPBW)², SLA)    A_V = −min(12·(θ'/HPBW)², SLA)
G   = Gmax − min(−(A_H + A_V), SLA)
```

Receivers (clients, attacker, map cells) are treated as isotropic with gain `G_rx`.
The attacker's directional antenna is assumed to be pointed at the target (best case for the attacker).

## 4. Received power and maps

```
RSS(T→R) = P_tx + G_tx(v) + G_rx − PL(T, R)           [dBm]
```

With several access points (micro-cell design, `router.mounts.micro.positions`) all APs share
power, band and antenna type, and `RSS(AP→R) = max_k RSS(AP_k→R)` — a client associates with,
and an eavesdropper listens to, the strongest AP.

Maps are evaluated at cell centres: `x = x0 + (i + 0.5)·cell`, `y = y0 + (j + 0.5)·cell`,
row-major `index = j·nx + i`.

* **Outdoor plane**: `z = rf.grids.outdoor.z` (1.5 m, a hand-held device).
* **Floor planes**: `z = floor.z + rf.grids.floor.dz` (1.2 m above each floor).

## 5. Protections (how each measure changes the inputs)

| Key | Effect |
|---|---|
| `lowPower` | `P_tx = 12 dBm` (from 20 dBm) |
| `directional` | router antenna = patch of the active mount, oriented by its `az`, `tilt` |
| `relocate` | router mount = `ceiling` (building centre, boresight straight down) |
| `microcells` | router mount = `micro`: two ceiling APs instead of one (web app only; not a Sionna preset) |
| `shieldWindows` | `loss.ext_glass += 25 dB (2.4 GHz) / 28 dB (5 GHz)` — metallised RF-shielding film |
| `shieldPaint` | `loss.ext_concrete += 20 dB / 24 dB` — conductive RF-shielding paint |
| `band5` | `f = 5.0 GHz` (material losses switch to the `"5"` column) |
| `pmf` | protocol: 802.11w Protected Management Frames → deauthentication blocked |
| `wpa3` | protocol: WPA3-SAE → no offline dictionary attack on captured handshakes; rogue AP cannot complete SAE |

The two protocol measures do **not** change the radio maps; they change which attacks are feasible.

## 6. Attack feasibility at an attacker position X

Attacker equipment `{G_att, S_att, P_att}` (`attack.equipment`), clients `c` (`clients`, `G_c = 0 dBi`,
`S_c = −88 dBm`), router AP.

| Attack | Condition (all in dBm / dB) |
|---|---|
| **Eavesdropping** (passive capture, handshake) | `RSS(AP→X) + G_att ≥ S_att` |
| **Deauthentication** (forged mgmt frames) | eavesdropping feasible **and** `max_c [P_att + G_att − PL(X, c)] ≥ S_c`, and `pmf` off |
| **Evil Twin** (rogue AP captures a client) | eavesdropping feasible **and** `∃c: P_att + G_att − PL(X,c) ≥ RSS(AP→c) + 3 dB` and `P_att + G_att − PL(X,c) ≥ −75 dBm`, and `wpa3` off |

The active attacks require the eavesdropping condition because the attacker must hear the network to
learn its BSSID, channel and client addresses. The tiers are therefore nested (Evil Twin ⊂ Deauth ⊂ Eavesdropping);
on maps the effective margins are `min(m_deauth, m_eav)` and `min(m_et, m_eav)` (continuous, so iso-lines stay clean).

Path loss is reciprocal, so `PL(X, c)` is computed with the client as the source and no
antenna gain. `RSS(AP→c)` uses the router's antenna pattern towards the client.

**Danger zone** = outdoor cells (outside the building footprint) where at least one attack is feasible.
The highest tier shown is Evil Twin > Deauth > Eavesdropping.

**Service coverage** (the trade-off check): fraction of the router-floor cells inside the
footprint — excluding the stair/elevator core `[−3, 1.2, 3, 8]`, which is not a service area —
with `RSS(AP→cell) ≥ −67 dBm` (0 dBi client).

**Hijack map** (interior, for the current attacker position, shown only if the attacker can eavesdrop there): floor cells where
`P_att + G_att − PL(X, cell) ≥ RSS(AP→cell) + 3` and `≥ −75 dBm` — devices there would
prefer the rogue AP.

## 7. Key statistics

* `area_eavesdrop`, `area_deauth`, `area_eviltwin` — m² of outdoor danger cells (outside the footprint).
* `max_leak_m` — largest distance from the footprint rectangle to an eavesdropping cell
  (`> grid` when the zone reaches the edge of the study area).
* `street_exposure` — % of cells on the main street + its sidewalks that allow eavesdropping.
* `coverage` — service coverage (§6).

## 8. Data exchange format (pre-computed maps → web app)

`web/src/data/sionna.json`:

```jsonc
{
  "generator": "sionna-rt <version>",           // or "mwm-numpy" for the reference model
  "created": "ISO-8601",
  "settings": { "max_depth": 5, "samples_per_tx": 1e7, "refraction": true, ... },
  "grids": {
    "outdoor": { "x0": -100, "y0": -70, "dx": 1.0, "nx": 200, "ny": 140, "z": 1.5 },
    "floor0":  { "x0": -18.5, "y0": -8.5, "dx": 0.25, "nx": 148, "ny": 68, "z": 1.2 },
    "floor1":  { ... "z": 4.8 }, "floor2": { ... "z": 8.4 }
  },
  "encoding": "uint8: v = round((RSS_dBm + 130)·2) clipped to [1,255]; 0 = no signal (< −129.5 dBm)",
  "scenarios": {
    "baseline": { "freq_ghz": 2.4, "tx_dbm": 20, "outdoor": "<base64>", "floor0": "<base64>", "floor1": "…", "floor2": "…" },
    "...": {}
  }
}
```

Scenario keys and their protection sets are listed in `building.json → scenarios`.
